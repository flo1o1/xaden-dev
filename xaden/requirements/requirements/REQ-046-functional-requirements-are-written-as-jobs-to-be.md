# Functional requirements are written as Jobs To Be Done; quality requirements as measurable goals

## Job

When I write functional requirements, I want them as jobs to be done, so I can focus on the user's situation and outcome instead of on features.

## Acceptance criteria

- type job needs a job story (When, I want to, so I can)
- type quality needs a quality goal
- both need acceptance criteria
- validated by check-requirements.sh
- TODO text warns and blocks releases
